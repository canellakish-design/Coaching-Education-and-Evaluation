# Handover: How Claude reaches Canvas (for Sideline)

Written 2026-11-17 from the cloud Claude Code session that has been running Harry's World History I
course. There are **no tokens, keys or passwords** in this document: only where they are kept and
what they are called.

## 1. Where it lives

- **Nothing runs on a McDonogh server, in a McDonogh Google account or as an Apps Script.**
  This session never built anything called "McDonogh infrastructure". If another chat used that
  phrase, it means something else, and this session doesn't know what.
- The Canvas connection is a **private GitHub repository plus GitHub Actions**:
  - Repo: `canellakish-design/world-history-canvas` (private, created 2026-07-15 under Harry's
    GitHub account `canellakish-design`, default branch `main`).
  - The code is ordinary Python scripts (`scripts/*.py`, 94 files) using `requests`, run by
    GitHub-hosted runners (`ubuntu-latest`, Python 3.12) from **workflow_dispatch** workflows in
    `.github/workflows/`.
  - Claude Code sessions (cloud, in the Claude app) write a script, push it to `main`, trigger a
    workflow, then read the job log. Claude never calls Canvas from its own container.
  - This session's own repo (`Coaching-Education-and-Evaluation`) only holds handover notes,
    which is why a search there finds no Canvas code.

## 2. Canvas address

`https://mcdonogh.instructure.com`. The REST API is under `https://mcdonogh.instructure.com/api/v1`.
Scripts read it from the `CANVAS_BASE_URL` secret, not from the code.

Main course: **8557** (CP World History I 2026–27; sections E1 20549, F2 20550, G1 20551).
Course **8316** (CORE) is the default target of `sync-canvas.yml` and must **never** be synced.

## 3. The token: where it is and how it was made

- **Where:** **GitHub Actions repository secrets** on `canellakish-design/world-history-canvas`:
  - `CANVAS_ACCESS_TOKEN`: the Canvas API token, sent as `Authorization: Bearer …`
  - `CANVAS_BASE_URL`: the Canvas address above
  - `CANVAS_COURSE_ID`: default course for `sync-canvas.yml` (points at CORE 8316)
  Workflows pass them to scripts as environment variables of the same names. You manage them
  in the repo's GitHub **Settings → Secrets and variables → Actions**.
- **How it was made: unconfirmed.** The secrets were set before this session started, and this
  session can't read secret metadata (GitHub blocks that path for Claude). It acts with Harry's
  teacher permissions in course 8557, which fits a **Canvas personal access token generated by
  Harry** (Canvas → Account → Settings → Approved Integrations → "+ New Access Token"). Harry
  should confirm that, and check the expiry date shown there.
- **For Sideline:** don't reuse this secret. Generate a separate Canvas token (same Canvas
  screen), name it e.g. "Sideline", and store it as a **Netlify environment variable** (e.g.
  `CANVAS_ACCESS_TOKEN`). Then either can be revoked without breaking the other.

## 5. How something outside calls it

**There is no web address and no API key for it.** It isn't a service. The only way in from
outside is to **start a GitHub Actions workflow**:

```
POST https://api.github.com/repos/canellakish-design/world-history-canvas/actions/workflows/run-script.yml/dispatches
Authorization: Bearer <GitHub token>
{"ref": "main", "inputs": {"script": "scripts/<file>.py", "course_id": "8557"}}
```
- Key needed: a **GitHub** token (fine-grained, this repo only, Actions: read and write;
  Contents: write if the caller also pushes scripts). It is not a Canvas key.
- It is **asynchronous and returns nothing**: you get `204`. To get results you have to find the run,
  wait 20–60 seconds, and read the job log. The script has to already be in the repo.
- Other workflows take simpler inputs: `canvas-query.yml` (`path`, `query`), `post-announcement.yml`,
  `update-announcement.yml`, `update-day-events.yml`, `canvas-agenda.yml`, `sync-canvas.yml`.

**Recommendation for Sideline:** don't go through GitHub. A Netlify function can call Canvas
directly at `https://mcdonogh.instructure.com/api/v1/...` with its own token from a Netlify
environment variable. That's synchronous, needs no repo, and returns JSON. Reuse the endpoint list
in `HANDOVER_PORTFOLIO_GRADING.md` Section 2.

## 6. Traps

1. **Calendar events visible to every section.** A course event titled "(Section E1)" is shown to
   all students. Section-only events must be one course event with
   `calendar_event[child_event_data][0][context_code]=course_section_<id>`. Helper:
   `scripts/section_events.py`. `run-script.yml` runs `make_events_section_specific.py` after
   **every** run as a guard, so even "read-only" runs can change events.
2. **`sync-canvas.yml` deletes module items that aren't in the JSON** (`content/modules-canellakis.json`),
   and with a blank course it targets CORE 8316. Always pass `course_id=8557` and a module filter.
3. **Canvas strips HTML comments** from assignment and page HTML. Don't use comment markers to find
   your own content again (`add_portfolio_grading.py` is broken because of this).
4. **Per-section due dates:** set them through assignment overrides. For a graded discussion, set the
   dates on the discussion's own `assignment_id`; same-name duplicate assignments exist.
5. **An Assignment module item with only a title** makes the sync create an empty 100-point
   assignment if no assignment of that name exists. Create the assignment first.
6. **Time zones:** Canvas wants UTC. Eastern is UTC−4 until 11/1, UTC−5 after.
7. **`attach_portfolio_rubric.py` deletes every other rubric in the course it runs on.** Never run
   it on another course, and never delete rubrics in past courses.
8. **GitHub limits inside Claude cloud sessions:** `gh` GraphQL commands (`gh workflow run`,
   `gh run list`) are blocked, so use `gh api` REST or the GitHub MCP tools. The secrets-metadata
   endpoint is blocked, and job logs sometimes 404 until the job finishes.
9. **Files that need a McDonogh sign-in:** student and team Google Docs often can't be opened by
   Claude's Google connection (Harry's personal account). Canvas copies of readings avoid this.
10. **Canvas "Google Drive tool" submissions** aren't in Harry's Drive. Use SpeedGrader only.
11. **Course pages edited by hand in Canvas** drift from the repo JSON, and the next sync
    overwrites them (seen with a textbook link on 11/16). Pull Canvas state before syncing.
12. **Nothing reaches students without Harry's explicit approval.** One Inbox message sent too
    quickly in October went to all three sections and was wrong.
